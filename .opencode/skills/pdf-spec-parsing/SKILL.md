# Парсинг PDF РД: текстовый слой → спецификации → vision

Итоги разбора «Санпропускник» (2026-09-08, отчёт:
`e:\Проекты Симрус\К1\К1 Архив\Kaluga K1\11 Работа\2026\Санпропусник\ОТЧЁТ_AI-парсеры_PDF_DWG_vs_наши_инструменты_2026-09-08.md`).

## Главный факт

**Текстовый слой CAD-PDF полон**: у 8/9 комплектов РД 12 781–311 300 симв./PDF, ВСЕ количества
спецификаций присутствуют обычным текстом, даже там, где `find_tables` возвращает 0 полезных строк.
`find_tables` покрывает ~35% спек-строк; anchor-парсер по тексту — ~90%+. Vision нужен только для
сканов, повёрнутых листов и рукописных правок.

## Порядок действий (decision tree)

1. **Текстовый слой**: `page.get_text()` постранично, плоский текст. Сначала — дамп ВСЕЙ страницы,
   не «шапки/указания». Цена: секунды. Это покрывает спеки ВК (л.13–17), ТС (л.23–24), ТХ (л.8–14),
   ОВ (л.18–20, 24–25), ЭМ (л.5–9, 13–20).
2. **Anchor-парсер спек** (если нужен структурированный JSON): искать шапку
   `Позиция | Наименование … | Единица измерения | Количество`, затем строки «имя … ед N,N».
   Отсекать титул-блок по маркерам: `Подп.`, `Дата`, `Инв.`, `Стадия`, `Листов`, `Копировал`,
   `ООО "ИСЕТ ГРУПП"`, `Разработал`.
3. **find_tables** — только для ruled-таблиц (ПС/СС/ЭМ спеки берутся им хорошо: 35/55/72 строк).
   Для спек CAD-печати без чистой сетки — не тратить время.
4. **Vision точечно** (1–3 страницы, не весь PDF): `page.get_pixmap(dpi=200–300)` → PNG →
   прочитать картинку моделью. Показано для: повёрнутых таблиц (дверная спека АР л.17),
   сканов (АС: 148 символов текста), рукописных правок.
5. **Ручное/человек** — последняя инстанция.

## Правила интерпретации (типовые ошибки ИИ и людей)

- **Scope страницы ≠ scope раздела**: спека на листе может быть на сегмент трассы (66 м), а ВОР — на весь
  участок (240 м). Сверяй диапазоны прежде чем объявлять расхождение (кейс ТС: стыки 12 vs 48).
- Число «из головы» — не факт: в кейсе «Санпропускник» chat-ИИ выдал UTP 2103/2200 м (в документе 1639,
  тройное совпадение журнал=спека=ВОР), ОК-1=25 (в тексте нет), двери 66 (его же таблица суммируется в 65).
- Каждое количество — с цитатой (`ЦИТАТА — дословная подстрока со страницы`) и номером страницы.
- Пересчёты ИИ (площади из экспликации, ±%) помечать как derived, не как факт.

## Проверка моделей (слепые прогоны, изолированная папка, цитаты обязательны)

- `opencode/big-pickle`: 9/9 в своей области, но режет область по буквальному прочтению промпта
  (перечисляй ВСЕ ожидаемые типы заголовков таблиц).
- `opencode/muse-spark-1.3`: 42/42, сам строит `get_pixmap` → vision-сверку, 279 с, аудит tool-calls чистый.
- Задание всегда: изолированная папка (вне Temp с чужими результатами), запрет чтения вовне,
  после прогона — аудит tool-calls по `opencode.db`.

## Целевые CLI DesignBase (развивать)

- `designbase ingest-pdf-texts <pdf> --building X` — постраничный дамп текста в чанки БД (provenance).
- `designbase extract-pdf-spec <pdf> --pages 13-17` — anchor-парсер → JSON
  `{page, pos, name, mark, unit, qty, raw}`.
- `designbase pdf-page-image <pdf> --page 17 --dpi 300` — PNG для vision.
- Golden-набор для eval: ТС ДК1 (11), ПС (18), СС (46), ЭМ (56), ВК л.13, ТС л.24.

## Питфоллы

- Проверять спек-страницы по диапазону листов из ведомости, а не первые 5 страниц PDF.
- `Единица измерения` может отсутствовать (спеки ДК — только Кол-во/Масса).
- Количество в спеке может стоять на другой строке блока, чем наименование (multi-row) —
  брать `get_text("blocks")` с координатами и сопоставлять по y.
- В PowerShell: `$env:PYTHONIOENCODING='utf-8'`; PyMuPDF: `import pymupdf` (fitz deprecated).
